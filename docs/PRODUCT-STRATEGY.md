# OpenDesign 产品定义与发展路径

日期：2026-09-16。状态：根据本轮用户方向形成的产品规划草案；具体优先级、目标和技术取舍为建议，不代表已上线或已授权迁移。

## 1. 产品定位

**OpenDesign 帮助人和 AI 从优秀设计中获得判断，通过沟通创造方案，再把方案编辑成可以实际交付的作品。**

核心价值是“知道为什么这样设计，并能做出来、改得动、交得出去”。面向教育工作者、企业产品与业务团队，以及服务他们的设计师和外部 Agent。

用户明确提出的方向：Library 结构化收藏优秀作品并形成设计总结；设计总监根据场景与需求提供专业建议；Studio 通过对话生成 HTML/PPT 型方案；可评估 DeepSeek Harness 等 Agent 架构；与已有教育和企业产品互联；产品先免费，未来探索高级收费。

措辞假设：“有评委的设计方案”暂按“有品位且经得起专业评审”理解。专业评审先落实为有依据的检查和修改建议，不预设虚拟评委团就是产品形态。

## 2. 产品分工与入口

| 模块 | 用户来做什么 | 核心产出 | 边界 |
| --- | --- | --- | --- |
| Library，品牌首页 | 找优秀作品、学设计、收藏参考 | 有来源、有策展观点的案例与专题；可供 Agent 使用的设计包 | 公共设计参考继续开放；私人收藏与公共入库分开 |
| 设计总监，贯穿全程的能力 | 说明场景，得到推荐与设计判断 | 需求简报、2–3 个方向、推荐理由、取舍和评审意见 | Skill 是工作方法；MCP 是调用通道；两者不自动等于专业判断 |
| Studio，对话创作空间 | 和 AI 一起把材料变成方案 | 可继续修改的 HTML 长文档或分页演示，以及可追溯版本 | PPT 式创作体验不等于完整 PPTX 兼容；先保证 HTML 交付 |
| Docs，精修与交付空间 | 手工改字、调版、批注、保存、导出 | 可靠的本机版本和交付文件 | 不复制 Studio 的完整 Agent 工作台；继续独立可用 |
| Connect，对外接入能力 | 从教育/企业产品、网站和 Agent 进入上述流程 | 受控的材料传入、设计能力调用、文档交接 | 按目的传最少信息；握手导入不等于同步、回写或共享权限 |

首页建议主导航：**发现 / 专题 / 收藏 / 创作 / Docs**。未登录可浏览公开资源；个人收藏先依据现有能力实现，团队收藏待身份权限完善。进入首页先看到精选与适用场景，创作入口清楚可见。

## 3. Library：从收集作品到积累可解释的设计知识

首页结构建议：本期策展 → 按任务浏览（课程、路演、研究报告、品牌表达等）→ 精选专题 → 优秀案例。不要把增加收录数量当首要成功指标。

每个案例至少回答：

1. 谁的作品、何时收录、来源目前是否可用；区分实时来源、历史快照、无法访问。
2. 解决了什么场景问题，面向谁；哪种情况下不适合借鉴。
3. 好在哪里：叙事、层级、字体、留白、色彩、图表与交互的具体证据。
4. 可迁移的原则与参数是什么；截图、样式参数和编辑者判断分别记录。
5. 哪些内容可引用、哪些资产可复用、哪些仅可参考；有设计分析不等于获得原作资产授权。
6. 人可以收藏、加入专题、带入 Studio；Agent 可按版本读取 Design Pack。

Design Pack 在现有契约上扩展，保留来源、版本、适用场景、约束和验证状态。新增面向教育/企业的优秀报告和演示案例时，不能把网站 UI 的评价尺度直接套用。

**最小策展验证建议：**先做 3 个场景专题，每个 5–8 个经过人工说明的案例，验证用户能否选出适合自己的方向。数量是试点规模建议，不是已完成库存。

## 4. 设计总监：把“品位”变成可讨论的判断

输入：目标、受众、使用场合、交付形式、资料证据、品牌约束、时间与修改要求。缺信息时先提出最关键的问题；明确假设后给方案，不反复问卷式盘问。

工作流程：

需求简报 → 检索可信案例 → 比较 2–3 个设计方向 → 推荐并解释取舍 → 用户选定 → 生成与评审 → 局部修订。

例如“给企业管理层讲一个产品机会”与“给初中生讲一个科学概念”，即使素材相同，也应在叙事密度、视觉层级、图表、语气和互动方式上给出不同理由。

评审覆盖：目标与受众匹配、事实来源、信息结构、视觉层级、一致性、阅读可达性、技术可编辑性。每条意见对应具体页面/段落/对象，包含问题、证据和建议；AI 建议与人工决定分别保留。

验收不能只看 AI 自评分。用固定任务对比“直接生成”与“经过设计总监”，由目标用户盲评适用性、清晰度、视觉质量，并记录采用原因和完成修改所需时间。评审应允许拒绝推荐，不能以参考库风格强行覆盖用户品牌。

## 5. Studio：以作品为中心的对话创作

建议第一版工作台有三个可理解的区域：资料与大纲、对话、作品预览。用户可以选择某一页或某段再说“这段讲清楚一点”“换成流程图”“保留这个版式”。

首个完整创作循环：

1. 提供需求和材料，确认目标及受众。
2. 总监给方向，先确认结构和 1–2 页视觉样张。
3. 生成整份方案；同时展示来源不足或布局异常。
4. 用户选择局部提出修改；Agent 提交候选版本或补丁。
5. 用户接受后形成版本；进入 Docs 做手工精修、批注与交付。

异步生成必须有清楚的执行状态、取消、失败说明、重试与会话恢复。一次失败不能伪装成成功样例。

**保护人工劳动是关键产品约束：**用户在 Docs 改过的标题、图片和排版，不应被下一次 Agent 生成覆盖。近期从 Docs 返回 Studio 时先上传/选择一个新基线；自动双向回写须等版本身份、变更提案和冲突处理成熟后再做。

生成链保留现有 Scene/manifest/来源标识与模型适配能力；对外可交付自包含 HTML。外部普通 HTML 仍走 Docs 保真导入，不强迫全部重编译成内部结构。PPTX/PDF 等导出能力逐项以真实文件验收，不在这一规划中宣称全面可用。

## 6. Agent 技术路径：DSH 先验证，业务契约保持独立

当前本机 `opendesign-studio-v0` 已有 Design Director 编译/校验、模型适配器、Design Pack 与 Agent 任务记录代码。旧文档也描述了公共生成配置与匿名会话隔离；本轮未重验 Studio 线上运行，不将这些记录当现时生产保证。

推荐评估 DeepSeek Harness 作为 Studio 的候选运行底座。其官方说明提供插件组合的模型、工具、技能、会话等能力，且仍标明开发者预览/API 持续迭代。它能帮助组织 Agent 执行，但不会自动提供我们的设计判断、编辑契约或作品交付质量。

先做一个独立适配试验：相同 Brief、相同模型、相同设计资源，分别由现有适配流程和 DSH 运行。保持 Studio UI、Docs 数据和现有生产配置不迁移。

必须验证：需求追问、案例工具调用、完整生成、局部修改、取消/恢复、用量记录、权限隔离、可定位错误、最终 HTML 导入与编辑。通过真实任务后再决定采用；如果接入收益不足，继续扩展现有适配层。

建议用 6 个固定任务，每类 2 个：课程讲解、企业提案、分析报告。先达到全部安全/保真门禁，再比较任务成功率、人工修订量、耗时与用量。测试预算和执行环境在开跑前明确；本轮不调用付费模型、不安装或改造运行时。

Studio 领域接口建议保持供应商无关：创建任务、读取进度、取消、恢复、提出修改、获取产物。内部可分别实现 DSH adapter 或现有模型 adapter；同样的设计 Skill/MCP 能力也允许外部 Agent 使用。

依据：[DeepSeek 官方 Harness 说明](https://www.deepseek.com/harness/)，2026-09-16 查阅。

## 7. 与教育和企业产品的连接

| 优先级 | 首个用例 | 上游提供 | OpenDesign 提供 | 闭环验收 |
| --- | --- | --- | --- | --- |
| P0 | DeepBrain 分析报告精修 | 用户选择的自包含报告 HTML | Docs 导入、修改、审阅与导出 | 在真实来源点击后完成保存、实际下载和重导入 |
| P1 | 教师备课/课程方案 | 教学目标、学生阶段、材料与授课时长 | 总监建议、课件/活动方案创作、Docs 精修 | 教师能实际使用并修改关键内容；保留教学事实来源 |
| P1 | 企业产品提案 | 客户问题、事实证据、品牌和决策诉求 | 方案结构、设计方向、演示稿或报告 | 负责人完成一份真实提案并交付给既定用途 |
| P2 | 项目成果与创作作品整理 | 用户主动选择的完成作品 | 私人收藏、模板沉淀、再次创作 | 复用减少准备时间；公开策展另行明确授权 |

每次交接保留来源产品、来源产物 ID、内容版本及用户可见状态；当前 v1 HTML 握手只承载文件，其他元数据作为下一版契约设计，不假装已有跨产品身份和数据同步。

跨产品业务身份与数据所有权仍归原系统。教育场景不默认上传学生个人资料，企业场景不默认传整份组织知识库。需要长期存储、组织权限或回写时，另行定义目的、访问范围、期限和删除规则。

## 8. 路线与验收顺序

按阶段推进；没有核实团队容量，不给承诺日期。建议每个开发迭代只承诺一个可验收用户结果，角色表示责任范围，尚非人员排班。

| 阶段 | 结果 | 状态/建议责任 | 进入下一阶段的证据 |
| --- | --- | --- | --- |
| Now A | Docs 开放交接真实可用 | 本地完成，公网联调待执行；接入工程 | DeepBrain → Docs → 编辑保存 → 下载重导入；MCP 链接清理与公开来源检查 |
| Now B | 三类产品分工、首页策展和总监输出确定 | 本文草案；产品负责人/策展 | 用课程和企业任务走查，同一需求能获得可解释的方向选择 |
| Next A | 小规模精选专题 + 总监推荐 | 待做；策展/设计能力工程 | 目标用户能找到并采用合适参考，解释与来源可核对 |
| Next B | Studio 单一任务的对话生成与局部修改 | 待做；创作工程 | 用一个真实提案完成 Brief → 方向 → 生成 → 两轮修改 → Docs 交付 |
| Next C | DSH 独立适配评估 | 待做；运行时工程 | 相同任务集通过权限、恢复、产物与成本用量比较，形成采用/暂缓结论 |
| Later A | 教育与企业各一个稳定接入 | 候选；对应产品负责人/接入工程 | 真实教师与企业负责人重复完成任务，明确数据所有权 |
| Later B | 团队空间、长期存储、品牌套件、高级额度 | 候选；产品/平台工程 | 有重复使用与付费意愿证据，身份/权限/保留/备份先定义 |

Next B 先补现有流程的一条闭环；Next C 可以作为其技术试验，但不使整个 Studio 交付被底座迁移阻塞。优先完成 Now A，Now B 先通过文档与样例推进，不同时重写三个前端。

明确延后：为了数量扩库、通用多 Agent 平台、大规模底座重写、完整 Office 兼容、实时多人共编、语音协作和支付接入。既有编辑可靠性、数据保全和必要修复不因新方向取消。

## 9. 免费与高级服务

建议免费保留：公共 Library 浏览与设计参考、基础 Skill/MCP、Docs 本机编辑与导出。临时交接有明确限额；Studio 模型生成消耗真实成本，适合有限试用额度或用户自带模型接入，不能把“免费产品”解释为无限模型调用。

未来收费围绕持续服务价值：团队品牌和权限、长期云端项目、企业私有知识与部署、高级生成额度及服务保障。价格、额度和套餐在使用数据与成本验证后确定。公开案例资产不因商业化被悄悄收回；用户作品不默认进入公共库。

## 10. 衡量是否在做对的事情

总目标建议：**每周被目标用户完成并实际用于教学、沟通或决策的作品数**。下载是交付证据之一，真实用途由试点回访确认，不用模型自评替代。

- Library：相关案例被采用率，以及用户能否说明其适用原因。
- 总监：建议采纳、人工盲评、需要纠正的事实与设计判断。
- Studio：从有效 Brief 到首次可用方案的时间、完整任务完成率、局部修改接受率。
- Docs/Connect：成功导入并继续编辑的比例、保存与文件交付完整性、失败与恢复。
- 业务：重复使用、单份完成作品的服务成本、真实高级服务需求。

当前不填虚构基线。先以 5 位目标试用者、10 份完成作品作为学习规模建议，汇总任务证据再设增长或转化目标；任何跨产品埋点需明确允许的事件字段，不上传文档正文。
