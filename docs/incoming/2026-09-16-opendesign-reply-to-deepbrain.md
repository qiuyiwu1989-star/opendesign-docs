## 协议边界

- 不依赖 SDK 才能使用 v1。协议升级应有独立版本和变更说明，不能静默改变已约定的 v1 行为。
- 当前接收端忽略未使用的文档字段；`name/html` 必须有效，已定义的可选 `generator/sourceUrl` 若存在仍需通过类型与长度校验。
- RESULT 的五种失败理由与你方一致。`ok:true` 在本机保存成功后返回；返回成功不意味着云同步、外部资源或任意图表编辑能力通过验收。
- Docs 从发送 READY 后开始等候 PAYLOAD，等待上限 15 秒。建议发送前已准备好 HTML；如果你方先同步打开空白窗口，再异步生成报告，应在报告就绪后才将该窗口导航至握手入口，并实际测试 opener 保留。避免在 Docs 已 READY 后才开始耗时生成。
- 用户确认弹窗可保持超过 15 秒；这个期限不限制用户确认。未收到有效 PAYLOAD 时 Docs 不知道可信来源 origin，不向 `*` 广播失败结果；来源客户端自行处理超时。保持不自动重发是正确的。

## 验收口径的两点修正

1. “双方都没做过真机握手”需改为“尚未完成双方真实产品的公网联调”。Docs 侧此前已在本地两个不同 origin 下，通过内置浏览器和原生 Safari 验证双窗口握手；但这不能代替你方已上线客户端的验收。
2. Docs 现有合成样本覆盖五张静态 SVG；你方新提到九种图表与 mermaid 静态替代，尚未逐一验收。请提供与当前导出器一致、无私密信息的九图合成 HTML（仍可放本目录），用于预发布检查。不能从“是 SVG”推导全部支持删除/移动：含 defs、marker、clipPath、id 或 url() 引用的图表可能显示正常，但保守编辑能力会禁用相关操作；逐图记录结果，再决定是否扩展支持。

## 深脑开关需核对

“只加 NEXT_PUBLIC_OPENDESIGN_DOCS_URL、不用重新构建”尚不能确认。若客户端直接读取此变量，Next.js 通常在 next build 时把值写入浏览器包，运行时仅加环境变量不能改变既有构建。如果通过动态服务端配置接口/属性传给客户端，则可采用运行时开关；需核对实际实现、缓存及必要重启步骤。

请在你方发布回执中标明配置读取位置和生效方式，不需要披露其他环境变量或任何密钥。依据：[Next.js 官方环境变量指南](https://nextjs.org/docs/app/guides/environment-variables#bundling-environment-variables-for-the-browser)。
