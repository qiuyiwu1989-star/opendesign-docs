# Studio 正式身份与作品认领实施方案

日期：2026-10-04。状态：代码只读审计与开发方案，未接入身份提供商、未迁移生产数据。

## 1. 已核实的基线

- `services/studio-agent/access.ts` 已区分 `anonymous` / `user`，严格按 kind + id 鉴权；HTTP 不接受客户端指定 owner。
- `http-service.ts` 目前仍只从签名匿名 Cookie 构造 Principal，且 jobs manager 也硬编码匿名身份。`user` 类型存在不等于用户登录已实现。
- `session.ts` Cookie 有效期 30 天，支持 Secure；没有账号、撤销会话、跨设备用户发现。
- `pg-projects.ts` 同时校验关系列 owner 与 `document.owner`。迁移时只改表列会使作品不可访问。
- `pg-jobs.ts` 任务主键含 owner，`binding.owner` 也参与鉴权，`request_hash` 包含原 owner；终态 payload 会被清除。仅更改 owner 会破坏幂等重试。
- `daily_usage` 按 UTC 日 + `anonymous:<id>` / `user:<id>` 计数；认领不能获得一份新的免费额度。
- `src/studio-remote-store.ts` 当前缓存按 taskId 关联云端项目，没有账号命名空间；登录/切换账号后不能直接展示旧账号缓存。
- 9 月 29 日已经发布匿名免费版，见 [发布回执](releases/20260929T052906Z-handoff.md)。旧计划中的数据库、Worker、公网待办属于历史状态。

## 2. 相邻项目可复用到什么程度

审计本机 `opendesign-studio-v0/studio/apps/`：

- `local-api/src/public-session.ts` 是匿名 scope，不提供正式公众账号。
- `admin-api/src/auth/session.ts` 提供签名、会话过期和撤销范式，但会话存储为进程内 Map。
- `admin-api/src/server.ts` 实际登录是管理员用户名/密码校验；`security/session.ts` 另有按 GitHub 不可变数字 ID 的管理员会话工具。两者都不能直接等同公共用户身份或现成 SSO。
- 可借鉴签名域隔离、精确 Origin、HttpOnly/Secure Cookie、登出撤销及测试方式。不要共享管理员 Cookie/密钥、把管理员 actorId 当公共账号，或读写旧 Studio 用户/项目数据。
- `dsh-deepbrain` 是工具/MCP 接入仓库，此次限定范围未发现可直接采用的用户会话验证契约。不能据此断言全部相邻系统没有账号。

**缺少的外部契约：** 真实公众身份签发方、不可变用户标识、服务端验证方式、允许的回调地址、会话有效期/撤销，以及测试账号。未取得这些证据前，不选择 Supabase/OIDC/GitHub 等供应商，也不发布模拟登录。

## 3. 可立即开发的三个小批次

### I1：身份适配边界与作品列表

- 定义服务端 `IdentityResolver`：输出已验证的 Principal 与会话展示状态；匿名实现保留。未知/失败的登录凭证明确拒绝，不悄悄创建新的身份。
- HTTP 与 PG jobs 构造都使用同一个已验证 Principal；客户端 userId、邮箱、任意代理头不能参与信任判断。
- 新增带分页的当前身份作品列表，只返回标题/项目 ID/更新时间/最新版本等必要元数据，不泄露他人 ID 或源码。标题需新增可信存储字段，不能假定现有项目已有标题。
- 客户端加入账号命名空间；切换身份中止旧轮询、隐藏旧缓存、隔离 pending 操作，再从服务端刷新。保留本地原稿且不自动上传。
- 开发期 fake resolver 只用于隔离测试，默认/生产仍为现有匿名服务。

### I2：匿名作品显式认领（隔离库先实现）

产品流程：登录后展示当前浏览器可证明拥有的作品，用户选择“将这些作品保存到我的账号”，展示数量、来源与不可逆归属变化。先认领选中作品；不默认认领浏览器全部内容。

必须同时验证仍有效的原匿名 Cookie 与当前已登录会话，并通过同源/CSRF 检查。输入只能是项目 ID 集合、操作 ID、预期版本；两个身份均由服务端解析。Cookie 丢失/过期不能凭项目 ID、邮箱、设备指纹补认领。

事务要求：

1. 按固定顺序锁定认领记录、相关项目与任务；统一约定 start/save/claim/worker 的锁序，避免死锁。所有新增请求在同一锁约束下检查认领状态，防止认领期间插入旧归属任务。
2. 有 queued/running 任务或仍有效 lease 时拒绝迁移，保留内容并提示先等待或取消后待进程退出。cancelled 但 lease 有效仍不可迁移。
3. 核验目标账号项目与任务容量；发生任务 ID 主键冲突时整批拒绝，不覆盖。更新项目列、document.owner、相关终态任务 owner 和 binding.owner；保留所有版本 ID、源码、接受/保存回执和 candidate 内容。
4. 单独处理请求幂等：现有 hash 含原 owner 且终态已无原请求，不能从终态重新计算。引入服务端不可变的认领来源/请求身份元数据，重试时据此校验原 hash；来源元数据不能授予旧身份访问权限。或先限制认领前所有待确认/待重试操作已收敛，但必须明确该方案不能完整解决历史请求重放。推荐前一种，并扩展归档校验与恢复测试。
5. 当日匿名额度转入目标账号：首次从同一匿名来源认领时，把该来源当日已用量合并到目标账号，保留全局计数且不重复累计。需持久认领账本、匿名来源与目标账号绑定及额度转移记录；防止同一来源拆分多账号、重复认领重置额度。额度超过上限允许保留作品，后续生成被限额。后续剩余匿名作品生成还需有明确合并计数策略，不能靠删除匿名计数规避限制。
6. 在同一事务写幂等操作回执（来源、目标、项目集、结果版本）；同一操作重放返回相同结果，不同参数拒绝。失败全部回滚；旧匿名身份立即不能再访问被认领项目。

不要永久把原匿名 scope 映射成登录用户：旧 Cookie 持有者不应因此获得整个账号的访问权限。

### I3：接入确定的真实身份服务与跨设备验收

取得并核验外部契约后实现唯一正式适配器；身份映射采用签发方 + 不可变 subject，映射为内部 user ID（当前 Principal id 上限 128 且字符受限，不能直接塞任意 subject）。正式会话支持过期与撤销，登录前后轮换会话，服务重启不应凭空注销全部用户。验收通过再准备独立发布包。

## 4. 验收清单

- 匿名与用户同 ID 隔离；伪造 Cookie/owner/代理头失败；过期和已撤销正式会话失败。
- 两个用户列表、项目、任务、候选、版本互不可见；切换账号看不到旧缓存或旧候选。
- 两设备同一账号发现并编辑同一作品；旧版本保存冲突明确显示且不覆盖。
- 双身份认领、重复认领、并发 start/accept/save、有效 lease、目标容量/任务 ID 冲突、事务中断都覆盖真实 PG 测试。
- 认领后版本与源 HTML 字节不变；候选可确认；旧 operationId / jobId 重试仍幂等；旧匿名访问失败。
- 免费额度跨认领、重试和多项目分批认领不重置；全局计数不重复；剩余匿名项目继续生成的计费身份有测试。
- 新认领元数据归档/备份/恢复后，原账号与候选回执仍有效。
- 真实浏览器：匿名草稿→登录→选择认领→另一设备继续编辑→退出→换账号验证隔离。测试通过不等于生产身份已接入。

## 5. 本轮结果与下一步

本轮只新增此方案，无运行代码、数据库、配置、生产身份变更。下一步可先做 I1 的适配边界与分页作品列表，使用现有匿名身份即能交付“找回当前浏览器云端作品”；正式登录和认领写入在 I2/I3 的明确契约与测试完成后接通。

## 6. 10 月 4 日后续交付：当前身份作品列表

已实现 `POST /api/studio-agent/projects/list`，保留现有同源、匿名 Cookie 与禁止请求指定归属的规则，没有接入登录或认领。

- 请求：`{ "limit": 20, "cursor": "上一页返回的 nextCursor" }`，字段均可省略；limit 为 1–50 的整数。
- 响应：`{ projects: [{ id, headRevision, createdAt, updatedAt, revisionCount }], nextCursor }`。末页游标为 null，不返回源码、候选、owner 或接受回执。
- 本地 JSON 与 PostgreSQL 使用同一摘要/游标校验契约。当前数据尚无独立标题字段，本批不从 HTML 提取标题，也不声称已有作品标题。
- 按 UUID 升序进行 keyset 分页，游标绑定身份类型和 ID。保存不会改变排序，不产生 offset 分页的重复项。游标不是授权凭据，每次依然按当前身份过滤。
- 列表不是跨请求数据库快照；分页期间新插入、排序靠前的 UUID，需要重新从首屏读取。此规则优先保证保存中的作品不因更新时间变化而在分页间跳动。
- 无效 limit/游标沿用 HTTP 服务参数错误 422；伪造 owner 400，错误 Origin 403。
- 针对性验证：4 文件 28 测试通过，覆盖两种仓储的相同分页契约、保存期间分页稳定、同 ID 不同身份隔离、JSON/真实 PostgreSQL HTTP、外部 Origin 与错误字段拒绝。正式账号、客户端列表 UI、IdentityResolver、认领、生产发布均未包含在本批。


## 7. 第二批：列表界面与统一身份边界

已接 Studio「我的云端作品」入口，按需读取列表、分页、刷新、失败重试和取消读取；打开时重新请求 projects/read，经服务端鉴权后才关联工作区。当前没有可信标题字段，因此显示真实作品 ID、更新时间和保留版本数。

重新打开优先复用原任务对应的本机操作记录，不丢弃 pending 保存/接受/生成操作；新发现作品仅建立云端缓存句柄，不创建或覆盖本地任务。候选与当前云端版本相同时保留，已过期候选在明确刷新后清除。列表不承担跨设备登录，也不恢复已丢失的匿名 Cookie。

服务端统一 IdentityResolver 输出的 Principal，项目与任务路径使用同一身份。本地匿名任务保留历史目录，预留用户任务使用隔离命名空间与固定长度散列目录。只有测试环境接受测试解析器；运行服务未新增账号配置入口，仍使用原签名匿名 Cookie，忽略客户端身份头。身份解析失败拒绝请求，不回退成匿名身份。

正式提供方适配、前端按账号缓存命名空间、登录/退出、匿名作品认领和跨设备验收仍待下一批，不能把这次提取边界视作正式登录。
