## 推荐定位
OpenDesign Studio：把专业材料变成有设计判断、可继续编辑的视觉方案。
首批用户：教师/课程负责人、企业产品与方案负责人。首批作品：课程演示、企业提案；长报告以现有HTML精修承接。
核心差异是连续工作流：材料有来源→方向有理由→作品可手改→Agent修改有范围→版本可恢复→跨产品交付。
Library提供设计参照；设计总监解释推荐与叙事；Docs提供精修底座；Connect供已有产品及Agent调用。
“Agent Design OS”保留为内部架构愿景，对外先讲用户能完成的作品，不让平台术语占据操作界面。

## 与旧工作台的变化
旧版长期占据中部的对话适合理解需求；有作品后推荐画布为中心，对话放右侧可切换属性。不是始终画布优先：空项目先材料/目标，有稿后工作台以作品为主。
状态分为：准备材料→确认大纲/方向→编辑作品→交付。阶段可回看，不强迫每次改字重新走向导。
选中页或对象后，AI修改范围显式显示；默认只改该范围。先看候选差异，再接受或拒绝。直接手改不需每次额外确认，支持撤销。

## 产品边界
首版全部免费。暂不扩成通用设计软件、完整Figma、完整Office或多Agent市场。
旧Studio的Scene IR和Docs任意HTML保持真实能力边界：同一产品入口可以连贯，但精修当前先关联副本，禁止声称自动无损双向同步。返回创作采用明确新基线。
真实AI、任意HTML自由布局、PPTX全格式保真均不能由原型推断已实现。

## 原型用于确认
1. 是否接受“专业材料→视觉方案”定位，以教育和企业两场景起步？
2. 有作品后是否采用左页面/图层、中画布、右对话/属性？
3. 是否接受选中范围→AI候选→确认写入版本的交互？

原型：docs/diagrams/2026-09-26-studio-prototype.html。所有材料、页面和AI回复为演示数据；不联网调用模型，不写真实项目。

用户确认（2026-09-26）：企业提案与课程并重。两个并列场景入口，共用工作台；提案需求摘要含受众/决策/证据，课程摘要含学习目标/学生阶段/活动与时长。原型提供两个场景切换，两者共用工作台。

原型脚本通过 Node 语法检查，无外部脚本或网络调用。浏览器安全策略阻止本地 file URL，因此尚未完成渲染及点击验收。原型仅在当前页面内保存，刷新重置；场景切换也会重置演示版本。
