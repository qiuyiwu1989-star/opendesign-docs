# 下一轮：Studio 与 HTML 可视化编辑

2026-09-24。用户确认沿三步推进 Studio，并要求 HTML 长文档提供类似 Figma 的图层及文字、图片、图标、容器移动调整能力。“常温”暂按上下文理解为“长文档”。

## 产品目标
作品为中心：左侧页面/图层，中间画布，右侧属性/对话。现有长文档仅支持内容块顺序移动，尚不满足自由调整要求。

## HTML 编辑路线
1. 图层树：嵌套层级、类型/名称、选择同步、定位及选择父级；文字、图片、SVG图标整体、容器均可识别。不得将所有DOM节点直接堆给用户。
2. 可视化布局操作：普通文档元素拖动排序及容器内布局调整；定位元素拖动/缩放；需要自由放置时提供明确的自由布局转换并可撤销。保留HTML响应式语义，不能全页默认absolute。
3. 属性：尺寸、间距、对齐、排布、字号、颜色；SVG首批整体移动/缩放，路径节点编辑单列后续能力。
4. 验收：选中→移动/改字/缩放→撤销/重做→保存刷新→导出重导入；桌面/窄屏检查；未选区域源码保留；父级/嵌套元素位置准确。

## Studio 三步
1. 旧版运行复核及复用清单：梳理v0/core/web/renderers/artifacts工程关系，确定主线；核实设计方向、Design Pack、生成任务、预览及导出，不以模块存在当作功能已验收。
2. 作品工作台：复用可靠能力，左侧页面/图层、中间作品、右侧对话/属性；需求表单成为可编辑摘要；需求、大纲、设计方向可回看。
3. 真实创作闭环：企业提案材料→澄清需求→方向→生成→指定一页两轮修改→Docs精修→导出。模型适配保留供应商无关，DSH独立评估。

## 数据边界
旧Studio Scene IR与Docs原始HTML不是同一文档模型。先明确产物与版本交接，人工修改后作为新基线，禁止未确认覆盖。当前全部免费；不增加收费流程。

## 交付顺序
先补上一版公网实际编辑验收，再完成旧版盘点与图层树技术验证；随后交付工作台与布局交互，最后接真实生成。每批独立验收和发布。
