## 1. 你们说对了一处，我方已改

**「只加 `NEXT_PUBLIC_OPENDESIGN_DOCS_URL`、不用重新构建」不成立。** 我核了线上产物：那个变量在 `next build` 时就被写进浏览器包，事后在服务器上加环境变量对已发布的包没有任何作用。站里另一个 `NEXT_PUBLIC_*` 开关早就踩过同一个坑，我们自己的配置样例里甚至写着「必须在执行 next build 的那台机器上就存在」——我上一封还是说错了。

**改法**：开关改成**服务端运行时配置**。

| 项 | 现在 |
| --- | --- |
| 配置读取位置 | 服务端路由 `GET /api/opendesign/config`（Node 运行时、`force-dynamic`、`Cache-Control: no-store`） |
| 变量名 | `OPENDESIGN_DOCS_URL`（**去掉了 `NEXT_PUBLIC_` 前缀**，地址不再进浏览器包） |
| 生效方式 | 改服务器配置 + 重启进程即可，**不需要重新构建发版** |
| 校验 | 必须是不带账号密码的 HTTP(S)，否则当作没配 |
| 可见性 | 只对已登录用户返回；未登录一律返回 `null` |
| 前端 | 菜单打开时问一次，结果在会话内缓存；取不到就不渲染这一项 |

## 2. 交接顺序改成「先备料，再开席」

按你们第 25 行的建议改了。**现在的顺序**：

1. 用户点击时同步 `window.open('about:blank')`（占住用户手势，避免被弹窗拦截）；
2. 在这个空白窗口还什么都没加载时，我方生成报告（取数、画图）；
3. 报告就绪后才 `popup.location.href = 'https://doc.opendesign.cc/#handoff=v1'`；
4. 收到 READY → 立刻发 PAYLOAD（内容早就备好了，不占你们那 15 秒）。

生成失败或超时（我方上限 30 秒）时，**不导航**、直接把空白窗口关掉，用户不会被送到你们页面上再被拒。这几条都有测试钉住：生成超时不导航、生成失败不导航、超过 5 MiB 不导航。

**`opener` 保留这件事我方仍未在真机验证**——理由与上轮相同（我方自动化浏览器把 `window.open` 开成同一标签页）。这是联调第一关，我方不会在验过之前开按钮。

## 3. 图表里不再有 `id` / `url()` / `defs` / `marker`

你们提醒「含 defs、marker、clipPath、id 或 url() 的图表，保守编辑能力会禁用相关操作」。我方去查了一遍，只有占比条用了 `clipPath + url(#…)` 做整条圆角。**已改成两端各自倒角的 path，不再需要 id 引用。**

现在九种图表的 SVG 里：没有 `id=`、没有 `url(#`、没有 `<defs>`、没有 `<marker>`（流程图的箭头是直接画的三角形，不是 marker）。已加一条测试守着，以后新增图表也过不去这道门。

**文档里仍有 7 个 `id`**：文末证据条目的 `id="ev-1"…`，用于正文上标锚点跳转（你们 Spec036 写明要保留 inline evidence links）。SVG 内部有 26 个 `<a href="#ev-N">`，都是**站内锚点**，不外链、不取资源。
